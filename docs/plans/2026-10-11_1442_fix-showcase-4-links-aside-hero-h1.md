# Fix: дефекты ручного тестирования пункта 4 — ссылки на строки, «Вне цепочки», иллюстрация, заголовок, мануал

## Контекст
План-виновник: `docs/plans/2026-10-11_1356_public-showcase-4-style-pipeline-scheme.md`
Мануал: `docs/manual/2026-10-11_1421_public-showcase-4-style-pipeline-scheme.md`
Фикс не является пунктом роадмапа: роадмап не трогаем.

## Проблема
Ручное тестирование пункта 4 (HEAD `c1c7acd`) нашло пять дефектов: ссылки на
строки `.md`-документов открываются на GitHub в режиме Preview без подсветки;
раскрытый `/plan-fix` в ряду «Вне цепочки» уезжает в конец ряда и
растягивается; звезда и вторая тарелка иллюстрации обрезаны дугой арки;
заголовок h1 на 1200px рвётся на «ИИ-» / «агентами»; в мануале пункта 4
неточности и противоречие §1 и §5.3.

## Причина
1. `repoFileUrl` (`site/src/repo.ts:9-15`) ставит якорь `#L…` сразу после
   пути; для `.md` GitHub показывает отрендеренный Preview, где якоря строк не
   работают. С `?plain=1` перед якорем строки подсвечиваются (проверено
   тестировщиком).
2. `site/src/components/PipelineScheme.css:184-187`: от 720px раскрытый
   `.step-aside.is-open` получает `grid-column: 1 / -1; order: 1` — весь `<li>`
   (кнопка + панель) переезжает в конец ряда на всю ширину, визуальный порядок
   кнопок (verify, fix-tests, plan-fix) расходится с порядком Tab.
3. `site/src/components/HeroArt.tsx:47,52-53`: звезда (`M164 30…`, y 30–46) и
   тарелка (`cx=476 cy=54`) лежат выше дуги `clipPath` `#hero-window`
   (эллипс с центром 320,140, rx 210, ry 120: в x≈156–172 верх дуги
   y≈55–65, в x≈465–487 — y≈53–67).
4. `site/src/App.tsx:14`: обычный дефис в «ИИ-агентами» — допустимая точка
   переноса строки.
5. Мануал писался до ручного прогона: не оговорены кэш (304) и favicon, число
   Shift+Tab, `?plain=1`, падение `steps.test.ts` на импорте; §1 описывает
   старое поведение «Вне цепочки».

## Окружение

- Сборка и стенд: `npm --prefix site run build`, затем

## Шаги

### Step 1 — test-repo-plain
- **Файл**: `site/src/repo.test.ts`
- **Изменение**: контракт `repoFileUrl` для строк markdown — `?plain=1` перед
  якорем:
  - тест «ссылка на диапазон строк»: ожидание →
    `${blob}/docs/specs/2026-10-11_public-showcase.md?plain=1#L3-L7`;
  - тест «ссылка на одну строку»: ожидание → `${blob}/README.md?plain=1#L5`;
  - новый тест «ссылка на строки не-markdown файла без plain»:
    `repoFileUrl('site/src/repo.ts', { from: 1, to: 2 })` →
    `${blob}/site/src/repo.ts#L1-L2`;
  - тест «ссылка на файл без строк» не меняется (`.md` без строк — без
    `?plain=1`, файлы команд открываются отрендеренными).
- **Проверка**: red: `npm --prefix site test -- src/repo.test.ts` — 2 failed
  (ожидается `?plain=1`, получено без него), 3 passed → green после `repo-plain`.

### Step 3 — aside-row-order
- **Файл**: `site/src/components/PipelineScheme.css`
- **Изменение**: в `@media (min-width: 720px)` правило
  `.step-aside.is-open { grid-column: 1 / -1; order: 1; }` заменить по образцу
  цепочки (`@media (min-width: 960px)`, `.scheme-chain > .step` и

- **Проверка**: iframe 1100px, раскрыть `/plan-fix`: у трёх кнопок одинаковый

## Решения
- Шагов шесть при лимите /plan-fix в пять: мануал (дефект 5) — отдельный
  docs-шаг в этом же фикс-плане по прямому указанию постановки задачи; шаги
  кода (1–5) в лимит укладываются.
- Дефект 4 — `white-space: nowrap` инлайн-стилем на span в `App.tsx`, а не
  неразрывный дефис U+2011: наличие глыфа U+2011 в подмножестве шрифта
  Unbounded не проверено, а инлайн-стиль держит правку в одном файле
  (инлайн-стили уже используются в `HeroArt.tsx`).
- `?plain=1` — только для `.md` и только со строками: файлы команд без строк
  по-прежнему открываются отрендеренными.

## Как воспроизвести баг (до фикса)
1. `npm --prefix site run build && npm --prefix site run preview -- --port 4176 --strictPort`.
2. Раскрыть `/plan`, открыть ссылку на документ — GitHub в Preview, строки

   штрих тарелки.
5. iframe 1200px — h1 «Конвейер разработки с ИИ-» / «агентами».
