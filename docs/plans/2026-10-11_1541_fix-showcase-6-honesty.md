# Fix: точность раздела «Как собран этот сайт» по ручному тестированию пункта 6

## Контекст
План-виновник: `docs/plans/2026-10-11_1503_public-showcase-6-build-story.md`
Мануал: `docs/manual/2026-10-11_1517_public-showcase-6-build-story.md`
Фикс не является пунктом роадмапа: роадмап `docs/roadmaps/2026-10-11_1236_public-showcase.md`
не трогаем, он только источник фрагментов.

## Проблема
Ручное тестирование пункта 6 (HEAD `e9edf88`) нашло в разделе «Как собран
этот сайт» формулировки, которые шире или неточнее документов прогона, тест,
поощряющий подгонку истории под PASSED и «отклонено: 0», необъяснённые
обрезанные фрагменты, подпись «строки N–N» для одной строки и дефекты
мануала пункта 6.

## Причина
1. `site/src/sections/build-story.ts`, стадия `review`, `lead`: «Отчёты ревью
   диффа лежат рядом с планами, и в них отклонённых замечаний нет» — звучит
   как свойство всего процесса, но в
   `docs/plans/2026-10-11_1303_public-showcase-1-harness-snapshot-review.md`
   строка 9 — замечание 2 с вердиктом «отклонено» и причиной, итог
   «отклонено: 1» (строка 33).
2. Стадия `fixes`, `lead`: «находки исправлены фикс-планами тем же путём …
   Fix-for» умалчивает, что `5997511` (мануал пункта 3) и `bbcf0c0` (запись
   роадмапа пункта 5) сделаны без фикс-плана, только с trailer `Fix-for:`.
3. Событие `verify-4`, `text`: «след первого остался только в «Решениях»
   плана» — неверно: шапка
   `docs/plans/2026-10-11_1356_public-showcase-4-style-pipeline-scheme-verify.md`,
   строка 5, тоже называет PARTIAL и его причину, и сайт показывает её
   фрагментом `build-verify4-repeat` рядом.
4. `site/src/sections/build-story.test.ts`, тесты «итоги проверки — PASSED,
   PARTIAL показан» и «в отчётах ревью диффа нет отклонённых замечаний»
   требуют, чтобы каждый показанный `-verify` был PASSED, а в `-review` стояло
   `отклонено: 0`: показать отчёт с другим итогом нельзя, тест поощряет
   подгонку. Нужна проверка соответствия: статус, который сайт заявляет для
   отчёта, совпадает со статусом в файле.
5. Фрагменты `build-plan4-criteria`, `build-plan5-criteria` (обрываются перед
   строками со словами, которых на сайте быть не должно) и
   `build-plan4-plugin` (начинается с середины абзаца по той же причине) на
   сайте не объяснены: подпись говорит только «начало критериев» или «конец
   записи».
6. `site/src/components/BuildStory.tsx:15` — «строки {fromLine}–{toLine}» даёт
   «строки 158–158» для однострочного фрагмента.
7. Стадия `result`: заголовок «Сайт принят и публикуется» и «Последний пункт
   сайта принят…» читаются как завершённость роадмапа; приняты пункты 3–5,
   финиш роадмапа (тег первой версии, доступ из РФ без VPN) — пункт 7.
8. Мануал пункта 6: §3/§4.8 — правки §5 в рабочем дереве и жёсткий порт;
   §4.8 — favicon и `data:` в Network не оговорены; §8 — `\|` внутри
   markdown-таблицы при копировании даёт неверную команду; §5.3/§5.4 — у
   `review-4` и `review-5` одинаковый текст, поиск по тексту находит оба;
   §6 — подмену статуса ловит тест, но действия нет; §4.9 — GitHub
   дорисовывает строки файла по мере прокрутки.

## Решения
- Шагов шесть: лимит /plan-fix в пять шагов по постановке не обязателен.
  Один файл — один шаг; браузерная приёмка — отдельный шаг без файла.
- Шаг `fragment-review1-rejected` стоит до red-теста: он не меняет типов,
  после него typecheck проходит; между red-тестом и `build-story-texts`
  typecheck и build не запускаются (`tsc -b` типизирует тесты).
- Тест проверяет соответствие заявленного статуса файлу, а не сам статус:
  показать отчёт с PARTIAL или отклонённым замечанием можно, приписать ему
  другой итог — нельзя. Связь с текстом — через заголовки событий стадий
  `verifier` и `review`; в стадиях `fixes`, `result`, `manual` заголовки
  статус не называют, там проверяется только `claim` против файла.
- Отклонённое замечание пункта 1 показано отдельным событием с фрагментом
  строки таблицы, а не только фразой во вводной: вводные стадий фрагментов не
  имеют, а у утверждения должна быть ссылка на строку.
- «Без цифр» про правки без плана: в тексте нет числа таких коммитов и их
  хешей, только вид правок (мануал, запись роадмапа).
- Финиш роадмапа назван словами «тег первой версии»: «v1» валит тест «нет
  цифр».
- Шаг `browser-acceptance`, пункт 1: в первой версии плана ожидалась ссылка
  `#L9-L9`; `site/src/repo.ts` для одной строки уже даёт `#L9`, и это верно
  для GitHub. Ожидание в шаге исправлено при реализации, код не менялся.
- Пометка обрезанного фрагмента — в `figcaption` после ссылки, текст —
  `PARTIAL_NOTE` в данных, чтобы его покрывали тесты на цифры и запрещённые
  слова.

## Как воспроизвести баг (до фикса)
1. `site/src/sections/build-story.ts`: `review.lead` — «в них отклонённых
   замечаний нет»; `verify-4.text` — «остался только в «Решениях» плана»;
   `accepted.title` — «Сайт принят и публикуется».
2. Заменить итог любого показанного `-verify.md` на `PARTIAL`, а сайт
   оставить — тест падает на «итог — PASSED», то есть требует подогнать файл,
   а не сайт.
3. Подпись фрагмента из одной строки — «строки N–N».
