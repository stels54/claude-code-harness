# Plan: README и описание шагов конвейера по тексту команд

## Контекст
Роадмап: docs/roadmaps/2026-10-11_1236_public-showcase.md, пункт 2

Пункт 1 положил в `harness/` опубликованный снимок ядра. Теперь нужно описать
именно его: записать в «Факты» роадмапа краткое описание каждой команды ядра и
агента `verifier` по фактическому тексту файлов `harness/` (вход, выход,
модель, где решение остаётся за человеком, как устроено ревью другой моделью) —
сайт (пункты 4–5) берёт описания оттуда — и написать корневой `README.md`,
который отвечает на вопросы «что это и для кого, шаги конвейера, установка,
что нужно для работы, какие команды не вошли, ограничения, дата снимка, где
сайт». Название конвейера по факту: «план → реализация → изолированная
проверка → ревью другой моделью».

## Окружение
Не требуется: docs-only план. Для проверок — `bash`, `grep`, `awk`, `jq`
(уже используются в пункте 1), `scripts/check-leaks.sh` со списком
запрещённых строк в `~/.config/harness-publish/denylist.txt` (вне git; его
строки не выводятся и не записываются в репозиторий),
`scripts/check-harness-refs.sh`.

## Финальный проход
- run-checks-repo — после всех правок, включая обновление статуса пункта в
  роадмапе.

## Критерии приёмки
1. В «Фактах» роадмапа есть запись пункта 2 по каждой из 8 команд ядра и по
   агенту `verifier`, плюс записи про ревью Codex, хуки и `CLAUDE.md`; каждое
   утверждение о модели, входе и выходе находится в тексте соответствующего
   файла `harness/`.
2. `README.md` содержит разделы «Что это и для кого», «Шаги конвейера»,
   «Установка», «Что нужно для работы», «Что не вошло», «Ограничения»,
   «Дата снимка и сайт»; в нём нет слов «Spec-Driven Development» и «SDD»,
   есть дата снимка `2026-10-11`, будущий адрес сайта с пометкой, что он ещё
   не опубликован, и ссылка на репозиторий; относительные ссылки живые.
3. Команды установки из README в пустом `HOME` ставят ядро (8 команд,
   `verifier`, исполняемые хуки, валидный `settings.json` с `hooks`,
   `CLAUDE.md`), а существующие `settings.json` и `CLAUDE.md` не меняют.
4. `scripts/check-leaks.sh` — 0 совпадений, `scripts/check-harness-refs.sh` —
   0 нарушений.

## Не делаем
- Правки файлов `harness/` (в том числе исправление `/code-review` под
  неотслеживаемые файлы) и рабочего `~/.claude`.
- Скрипт установки, `Makefile` и прочие новые инструменты: установка — блок
  команд в README.
- Автоматическое слияние существующих `settings.json`/`CLAUDE.md` с
  фрагментами ядра — только инструкция вручную.
- Описание содержимого `from-linear`, `review`, `git-report`, скилла `lessons`.
- Цифры статистики, слова «Spec-Driven Development» и «SDD», заявление о
  стадии спецификации как части конвейера.
- Сайт, корневой `CLAUDE.md` с командами проверки сайта — пункт 3.
- Английскую версию README.

## Решения
- Дата снимка → `2026-10-11`; сайт → `https://stels54.github.io/claude-code-harness/`,
  в README как будущий адрес, сайт ещё не опубликован; репозиторий →
  `https://github.com/stels54/claude-code-harness` (решение пользователя).
- Описания шагов в «Фактах» → по фактическому тексту команд в `harness/`, без
  домыслов: вход, выход, модель из frontmatter (если указана), STOP-точки,
  устройство ревью Codex (`codex exec --sandbox read-only`) (решение
  пользователя).
- Не вошедшие команды → одной строкой: `from-linear`, `review`, `git-report`,
  скилл `lessons`, без описания содержимого (решение пользователя).
- Название конвейера → «план → реализация → изолированная проверка → ревью
  другой моделью»; без «Spec-Driven Development»/«SDD», без цифр статистики
  (решение пользователя, решение 9 спецификации).
- Строки списка запрещённых строк никуда не записываются; перед коммитом —
  `scripts/check-leaks.sh` и `scripts/check-harness-refs.sh` (решение
  пользователя).

## Допущения
- Записи «Фактов» пишет этот план, а не синк /implement: так решено в
  «Решениях» роадмапа (описания шагов — в «Фактах» пункта 2). Синк /implement
  после verify дописывает только то, что вскроется по ходу.
- «затрагивает» у записей шагов — 4 и 5 (схема и «Устройство» берут
  описания отсюда), у хуков и `CLAUDE.md` — 5.
- Для команд без поля `model` пишется «в frontmatter не задана», без
  утверждений о том, какую модель выберет Claude Code.
- Названия разделов README фиксированы планом, чтобы проверка шла по
  заголовкам; дата снимка и сайт объединены в один раздел.
- Известный дефект `/code-review` (неотслеживаемые файлы вне `git diff HEAD`)
  отражается в «Ограничениях» README как свойство снимка.
- Одноимённые файлы в `~/.claude/commands`, `agents`, `hooks` при установке
  заменяются — README предупреждает о резервной копии, но не защищает от
  перезаписи: это файлы самого ядра.
