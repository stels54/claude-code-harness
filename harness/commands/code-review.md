Проведи независимое ревью изменений кода другой моделью и внеси принятые правки.

$ARGUMENTS

## Аргументы

Оба необязательны, порядок любой.

- **Путь к плану** (`docs/plans/<ГГГГ-ММ-ДД_ЧЧММ>_<имя>.md`) — контекст
  намерения для ревьюера и имя для отчёта. Не передан — возьми самый свежий
  план в `docs/plans/`: последний по сортировке имён; файлы с суффиксами
  `-verify.md` и `-review.md` — производные, не планы. Если у него уже есть
  `-review.md` — STOP, спроси, ревьюить ли повторно.
- **Git-диапазон** (`abc123..HEAD`, `HEAD~2`) — что ревьюить. Не передан —
  незакоммиченные изменения: working tree и index против `HEAD`.
  Дифф пуст — STOP: «Нечего ревьюить».

## Шаг 0. Preflight

1. `command -v codex`. Бинаря нет — одна строка «Code review: ⏭️ (codex не
   установлен)», команда завершена, файл отчёта не создавай.
2. Зафиксируй `git status --short` и `git diff --stat <диапазон>`. Список
   изменённых файлов — область ревью и область допустимых правок.

## Шаг 1. Ревью (Codex)

```bash
codex exec --sandbox read-only "Ты — ревьюер кода, файлы не меняешь.
План задачи: <путь к плану> — прочитай как контекст намерения.
Соответствие плану проверяется отдельно — его не оценивай.
Проревьюируй изменения <диапазон | 'незакоммиченные изменения, git diff HEAD'>
и относящийся к ним код репозитория.
Ищи: дефекты логики, необработанные ошибки и граничные случаи, регрессии
в соседнем коде, проблемы безопасности, нарушения контрактов (типы, API,
схема БД, события). Стиль, форматирование, именование и «я бы сделал
иначе» — вне объёма.
Выведи нумерованный список замечаний: файл/строка → суть → серьёзность
(критично / важно / мелко) → предложение правки одной фразой.
Новых фич не предлагай. Контекста обсуждения у тебя нет — это намеренно."
```

`git status --short` после — дерево не изменилось; изменилось — откати
правки ревьюера и отметь это в отчёте.

## Шаг 2. Разбор замечаний

Каждое проверь по коду сам, механически не принимай. Вердикт — один из трёх:

- **исправлено** — замечание верно, правка локальна: не меняет подход,
  не выходит за файлы диффа. Внеси сразу.
- **STOP** — замечание верно, но правка меняет подход или структуру, выходит
  за файлы диффа, требует нового поведения или правки существующего теста
  (assertion, фикстуры, ожидаемые значения). Не делай: сформулируй вопрос
  по правилам CLAUDE.md, «Вопросы ко мне», и жди решения. Принятое решение
  реализуется отдельным /plan, не в обход.
- **отклонено** — одной строкой почему.

Правила правок:
- Только по принятым замечаниям, без попутного рефакторинга.
- В тест-файлы можно только добавлять кейсы на найденные граничные случаи.
- После правок прогони тесты затронутых файлов командой проекта
  (Makefile → scripts в package.json/composer.json → CI → README).
  Красный тест — не подгоняй: откати правку, замечание → STOP.
- Один цикл: повторное ревью после правок не запускай.

## Формат отчёта

Сохрани в `docs/plans/<имя-плана>-review.md`, где `<имя-плана>` — имя файла
плана целиком, с дата-префиксом и без `.md` (как у `-verify.md`).
Конвенция — CLAUDE.md, «Именование документов».

```markdown
# Code review: <название плана>
**Дата**: <дата>
**План**: <путь к файлу плана>
**Дифф**: <диапазон | незакоммиченные изменения>, <N> файлов

| № | Замечание | Файл | Серьёзность | Вердикт | Что сделано |
|---|-----------|------|-------------|---------|-------------|
| 1 | ... | ... | критично | исправлено | <файл — суть правки> |
| 2 | ... | ... | важно | STOP | вопрос 1 ниже |
| 3 | ... | ... | мелко | отклонено | <почему> |

## Проверка после правок
`<команда>` — <итоговые строки вывода> | «правок не было»

## Ждёт решения
<нумерованный блок вопросов по CLAUDE.md | —>

## Итог
Замечаний: N · исправлено: X · отклонено: Y · ждёт решения: Z
```

В чат выведи таблицу и «Ждёт решения», без пересказа.

## По завершении

Правки внесены и у плана уже есть `-verify.md` — верификация устарела:
запусти субагента `verifier` с заданием «Проверь план <путь к файлу плана>»,
без summary правок. Итог передай дословно. Дальше — по правилам /implement:
PASSED → предложи коммит по CLAUDE.md, «Коммиты»; DEFERRED → спроси,
принимаешь ли.
