Почини упавшие тесты.

$ARGUMENTS

## Что делать

`$ARGUMENTS` — имя упавшего теста, вывод ошибок или stacktrace. Аргумент обязателен: он задаёт и что чинить, и область работы.

Если аргумент пуст — STOP с сообщением: «Передай имя упавшего теста или вывод ошибок». Не запускай suite вслепую, чтобы найти, что сломано.

Если в репозитории несколько suite (backend / frontend), работай только с тем, к которому относится переданный вывод. Во второй не лезь, даже если знаешь, что там тоже красно.

## Шаг 0. Разведка

### Раннер
Определи по виду вывода в `$ARGUMENTS`: PHPUnit, pytest, vitest/jest, cargo, go test и т.д. Дальше весь синтаксис — этого раннера, а не привычного по умолчанию.

### Команда прогона
Раннер ≠ команда запуска в этом проекте. Найди фактическую, по порядку:

1. `Makefile` — таргеты `test*`
2. `package.json` → `scripts`
3. `composer.json` → `scripts`
4. CI-конфиг (`.github/workflows/**`, `.gitlab-ci.yml`)
5. README

Бери ту, что уже есть в проекте. Новых инструментов и своих команд не заводи. Если ничего не нашлось — спроси, чем прогонять, и не выдумывай.

### Фильтр
Определи флаг фильтрации по раннеру: `--filter` (PHPUnit), `-k` (pytest), паттерн имени (vitest/jest), `cargo test <name>`.

Проверь, что фильтр пробрасывается через найденную команду — make-таргеты и npm-скрипты часто его глотают. Если не пробрасывается или раннер фильтр не поддерживает — гоняй ближайший файл или директорию, но не весь suite.

## Процесс

### 1. Определи причину падения
Для каждого упавшего теста установи причину:
- **Баг в коде** — реализация не соответствует тесту
- **Устаревший тест** — тест проверяет поведение которое намеренно изменилось
- **Окружение** — проблема с моками, фикстурами, конфигурацией
- **Типы** — несоответствие типов после рефакторинга

Не чини тест если причина неочевидна — сначала сообщи гипотезу и спроси подтверждение.

### 2. Чини в правильном порядке
- Сначала исправляй **код**, не тест
- Тест трогай только если поведение намеренно изменилось
- Не удаляй тесты — только если они дублируют другой

### 3. После каждого исправления
Перезапусти только затронутый тест — командой и фильтром из шага 0. Не весь suite.

### 4. Финальный прогон
Когда все тесты зелёные — прогони полный suite той же командой без фильтра, чтобы убедиться что ничего не сломал попутно.

## Запрещено
- Комментировать упавшие тесты
- Менять assertions чтобы тест прошёл
- Делать рефакторинг попутно

## Формат отчёта

Пример показывает **форму** — имена тестов и файлов бери из фактического вывода:

```markdown
## Результат

| Тест | Причина | Что исправлено |
|------|---------|----------------|
| login: отклоняет истёкший токен | Баг в коде | auth-сервис — неверное условие сравнения |
| api: возвращает JSON | Устаревший тест | обновлён expected статус 200→201 |

**Итог**: <N> тестов починено. Прогон `<команда>`: ✅ / ❌
```
