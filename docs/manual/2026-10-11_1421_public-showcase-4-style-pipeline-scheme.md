# Мануал: Визуальный стиль и кликабельная схема конвейера

План: `docs/plans/2026-10-11_1356_public-showcase-4-style-pipeline-scheme.md`
Верификация: `docs/plans/2026-10-11_1356_public-showcase-4-style-pipeline-scheme-verify.md`
Ревью: `docs/plans/2026-10-11_1356_public-showcase-4-style-pipeline-scheme-review.md`

## 1. Назначение

Пункт 4 роадмапа `docs/roadmaps/2026-10-11_1236_public-showcase.md` дал:

- **Стиль** (`site/src/index.css`): тёплая бумажная палитра с закатным
  градиентом сверху, тёмные «чернила» для текста и линий, акценты: закатный
  оранжевый (ссылки), розовый, охра, приглушённый бирюзовый, фиолетовый
  (подписи, фокус). Тёмная тема — по `prefers-color-scheme: dark`
  («сумеречная комната»). Шрифты локальные, лицензия OFL
  (`site/public/fonts/`): Unbounded — заголовки, Literata — текст,
  JetBrains Mono — фрагменты документов.
- **Шапка** (`site/src/App.tsx`, `site/src/components/HeroArt.tsx`): строка
  «Claude Code · команды и агент проверки», заголовок «Конвейер разработки с
  ИИ-агентами», подзаголовок «план → реализация → изолированная проверка →
  ревью другой моделью», линейная SVG-иллюстрация (арочное окно, шпили
  города, планета с кольцом, летающие тарелки), ссылки «Репозиторий на
  GitHub» и «README», строка «Остальные разделы сайта в работе.».
- **Раздел «Конвейер»** (`<section id="pipeline">`,
  `site/src/components/PipelineScheme.tsx`): цепочка из шести шагов с
  номерами 1–6 — `/roadmap` (метка «опционально»), `/plan`, `/implement`,
  `verifier`, `/code-review`, `/manual`; группа «Вне цепочки» — `/verify`,
  `/plan-fix`, `/fix-tests`. Каждый шаг — кнопка; раскрыт не больше одного
  шага, повторное нажатие сворачивает. Панель шага: «Что делает», «Вход»,
  «Выход», «Решение за человеком», «Модель» (только у `/roadmap`, `/plan`,
  `/implement`, `verifier` — `opus`), ссылка «Файл команды: harness/…»; у
  шагов цепочки — подпись и ссылка на документ со строками и сам фрагмент;
  у шагов вне цепочки — строка «Документа этой команды в репозитории нет.».
- **Фрагменты** вырезаются при сборке плагином `site/fragments-plugin.ts`
  (виртуальный модуль `virtual:pipeline-fragments`) по маркерам из
  `site/src/pipeline/fragment-sources.ts`; пропавший маркер — ошибка
  `vite build`. Документы целиком в бандл не попадают.
- **Ссылки на репозиторий** собираются от одной базы — `REPO_URL` и
  `REPO_REF = 'main'` в `site/src/repo.ts` (пункт 7 поменяет `REPO_REF` на
  тег).
- Раскладка: до 960px цепочка — вертикальный список «таблеток» с линией
  слева; от 960px — ряд из шести «станций» на горизонтальной линии, панель
  раскрытого шага на всю ширину под рядом. Группа «Вне цепочки» от 720px —
  три колонки, раскрытый шаг растягивается на всю ширину.

## 3. Pre-requisites

- Node.js 22, npm 10; зависимости: `npm --prefix site ci` (если
  `site/node_modules` нет).
- Chrome или другой браузер с DevTools.
- Порт 4173 свободен: `lsof -iTCP:4173 -sTCP:LISTEN` → пусто.
- Сборка и preview из корня репозитория:
  ```bash
  npm --prefix site run build
  npm --prefix site run preview -- --port 4173 --strictPort
  ```
  Адрес: `http://localhost:4173/claude-code-harness/`.
- Для §4.8 — push в `main` сделан тимлидом (агент push не делает).

## 4. Happy path

### 4.1. Загрузка и сеть

**Действие**: открыть `http://localhost:4173/claude-code-harness/`,
DevTools → Network, включить «Disable cache», перезагрузить страницу.
**Ожидание**:
- вкладка браузера — «Конвейер разработки с ИИ-агентами»;
- все запросы к `localhost:4173`: документ, `assets/index-<хэш>.js`,
  `assets/index-<хэш>.css`, `favicon.svg` и шесть шрифтов
  `/claude-code-harness/fonts/`: `unbounded-`, `literata-`,
  `jetbrains-mono-` × `cyrillic-wght-normal.woff2`, `latin-wght-normal.woff2`
  (статус 200);
- запросов к другим доменам нет (фильтр Network по `-domain:localhost` —
  пусто), картинок PNG нет;
- в Console ошибок нет.

### 4.2. Внешний вид, светлая тема, широкий экран (≥ 960px)

**Действие**: окно шире 960px, системная тема светлая.
**Ожидание**:
- фон — тёплый кремовый с розово-персиковым свечением сверху; заголовок
  крупным широким гротеском (Unbounded), текст — антиквой (Literata),
  подзаголовок курсивом;
- иллюстрация — только тонкие линии и полупрозрачная заливка арки,
  растровых картинок нет; сюжет картинки-ориентира (стол, кот, ковёр) не
  повторяется;
- в разделе «Конвейер» шесть номеров 1–6 в кружках на горизонтальной линии,
  под ними `/roadmap` с меткой «опционально», `/plan`, `/implement`,
  `verifier`, `/code-review`, `/manual`; ниже «Вне цепочки» — три
  пунктирные «таблетки» в ряд.

### 4.3. Тёмная тема

**Действие**: DevTools → ⋮ → More tools → Rendering → «Emulate CSS media
feature prefers-color-scheme» → `dark` (или тёмная тема ОС).
**Ожидание**: фон тёмный фиолетово-коричневый, текст кремовый, ссылки —
светло-оранжевые, линии иллюстрации и схемы светлые полупрозрачные; текст
читается, нигде нет тёмного текста на тёмном фоне. Раскрыть `/code-review`
(§4.4) — фон фрагмента тёмный, текст фрагмента светлый.

### 4.4. Раскрытие шага мышью

**Действие**: клик по `/plan`.
**Ожидание**: кнопка подсвечена (рамка закатного цвета), под ней панель:
- «Что делает» — «Составляет план реализации, кода не пишет. После
  сохранения плана — кросс-ревью другой моделью (Codex, codex exec --sandbox
  read-only): …»;
- «Вход», «Выход», «Решение за человеком», «Модель» — `opus`;
- «Файл команды: harness/commands/plan.md»;
- подпись «Шаг плана пункта 3 (каркас сайта): docs/plans/2026-10-11_1333_public-showcase-3-site-skeleton-pages.md, строки 95–106»;
- фрагмент моноширинным шрифтом, начинается с `### Step 4 — vite-base`.

**Действие**: клик по `/implement`.
**Ожидание**: панель `/plan` закрылась, открылась `/implement`; фрагмент
начинается с `- Проверка шага scaffold-vite-site`, строки 451–454.

**Действие**: повторный клик по `/implement`.
**Ожидание**: панель закрыта, все шаги свёрнуты.

### 4.5. Клавиатура

**Действие**: кликнуть по пустому месту страницы над заголовком, нажимать
Tab.
**Ожидание**: фокус идёт: «Репозиторий на GitHub» → «README» → кнопка
`/roadmap` → `/plan` → … → `/manual` → `/verify` → `/plan-fix` →
`/fix-tests`. У сфокусированного элемента видна обводка 2px (фиолетовая в
светлой теме, оранжевая в тёмной) с отступом от рамки.

**Действие**: фокус на кнопке `verifier`, Enter.
**Ожидание**: панель `verifier` раскрыта; Tab переводит фокус на ссылки
внутри панели («harness/agents/verifier.md», ссылка на документ), затем на
следующую кнопку `/code-review`.

**Действие**: Shift+Tab обратно на `verifier`, Space.
**Ожидание**: панель свёрнута. Space ещё раз — раскрыта снова; страница при
Space не прокручивается.

## 6. Edge cases

- **Тексты-запреты**: на странице нет слов «SDD» и «Spec-Driven
  Development» (Ctrl+F) и нет цифр статистики; в бандле:
  `grep -c -E 'SDD|Spec-Driven' site/dist/assets/*.js` → 0;
  `grep -c 'Пункт 5 — Разделы' site/dist/assets/*.js` → 0 (документы
  целиком в бандл не попали).
- **Внешние адреса в статике**: `grep -rhoE '(src|href)="[^"]*"|url\([^)]*\)'
  site/dist --include='*.html' --include='*.css' | grep -E 'https?://|//'` →
  пусто. В JS встречаются `http://localhost:4173/claude-code-harness/` и
  ссылка на README — это текст фрагмента из мануала пункта 3, не запрос.
- **Шрифт не загрузился** (заблокировать `*.woff2` в DevTools → Network
  request blocking): текст показывается системными шрифтами, вёрстка не
  ломается.
- **Символы вне подмножеств шрифтов** (стрелки «→», эмодзи ⏭️/❌/📝 в
  фрагментах) рисуются системным шрифтом — багом не считать.

## 7. Фронтенд-нюансы и известные ограничения (багом не считать)

- Тёмная тема не проверялась агентом в браузере: расширение не эмулирует
  `prefers-color-scheme` — её проверяет человек (§4.3). Переключателя темы
  на странице нет по плану.
- Состояние раскрытия не сохраняется: после перезагрузки все шаги
  свёрнуты; глубоких ссылок на шаг нет.
- Ссылки ведут на `main`, а не на тег (переход — пункт 7): если документ
  поправили после push, подсветка строк на GitHub может сместиться
  относительно показанного фрагмента до следующей сборки.
- `scripts/check-links.sh` не видит ссылки, собранные `repoFileUrl()`; их
  пути проверяет тест данных схемы.
- Подсветки синтаксиса во фрагментах нет — показывается исходный markdown.
- Разделы «Зачем», «Устройство», «Ограничения», подвал — пункт 5; на
  странице только шапка и «Конвейер».
- В окне Chrome через расширение ширина не сужается ниже ~606px — агент
  проверял 360px в iframe; человек проверяет через device toolbar (§4.6).
