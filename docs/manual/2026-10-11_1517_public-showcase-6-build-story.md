# Мануал: Раздел «Как собран этот сайт»

План: `docs/plans/2026-10-11_1503_public-showcase-6-build-story.md`
Верификация: `docs/plans/2026-10-11_1503_public-showcase-6-build-story-verify.md`
Ревью: `docs/plans/2026-10-11_1503_public-showcase-6-build-story-review.md`

## 1. Назначение

Пункт 6 роадмапа `docs/roadmaps/2026-10-11_1236_public-showcase.md` заменил
строку-заглушку «Раздел «Как собран этот сайт» в работе.» разделом, который
показывает реальный прогон пунктов 3–5 (сайт) фрагментами документов.

- **Данные** — `site/src/sections/build-story.ts`: `BUILD_STORY` (заголовок
  «Как собран этот сайт», вводная, восемь стадий) и `SELF_PLAN` (ссылка «план
  этого раздела»). Разметка — `site/src/components/BuildStory.tsx`, стили —
  `site/src/App.css` (`.build-stage`, `.build-stage-lead`, `.build-events`,
  `.build-self`; фрагменты переиспользуют `.step-fragment` схемы).
- **Фрагменты** вырезает при сборке плагин `site/fragments-plugin.ts` по
  ключам `build-*` в `site/src/pipeline/fragment-sources.ts` (33 ключа
  плюс существующие `roadmap`, `implement`, `verifier`, `code-review`);
  `end: null` — до конца файла. Пропавший маркер валит `vite build`.
- **Стадии по порядку** (`h3` внутри `<section id="build">`):
  1. «Постановка» — «Спецификация — вручную»;
  2. «Планы» — «Пункт 3: каркас сайта и публикация», «Пункт 4: стиль и схема
     конвейера», «Пункт 5: остальные разделы»;
  3. «Отклонения» — проверка шага пункта 3; «Пункт 4: реализация
     остановилась на решении пользователя»; «Пункт 5: hh.ru в подвале не
     показывается»; «Пункт 5: другой порт приёмки»; «Пункты приняты без
     ручных проверок»;
  4. «Отчёты агента проверки» — пункт 3 PASSED с отложенными пунктами;
     «Пункт 4: сначала PARTIAL, затем PASSED» (след первого прогона — в
     «Решениях» плана и в шапке повторного отчёта); пункт 5 PASSED;
  5. «Ревью другой моделью» — вводная: в показанных отчётах пунктов сайта и
     фикс-планов отклонённых замечаний нет, в отчёте пункта 1 одно
     отклонено; «Пункт 1: одно замечание отклонено», «Пункт 3: два
     замечания, оба исправлены», «Пункт 4: замечаний нет», «Пункт 5:
     замечаний нет»;
  6. «Исправления по итогам ручного тестирования» — вводная: правки кода шли
     фикс-планами, часть правок документации — коммитами с Fix-for без
     фикс-плана; «Исправления пункта 4», «Исправления пункта 5»;
  7. «Итог» — «Пункты сайта приняты, роадмап не завершён» (финиш — тег
     первой версии и доступ из РФ — в пункте 7);
  8. «Что проверялось руками» — «Выполнено: ядро в чистом окружении»,
     «Отложено: РФ без VPN, телефон, Network, тёмная тема».
- **Фрагмент** — `figure`: подпись и ссылка «`<путь>`, строки A–B» на
  `https://github.com/stels54/claude-code-harness/blob/main/<путь>?plain=1#LA-LB`
  (фрагмент из одной строки — «строка N» и `#LN`), под ней свёрнутый
  `<details>` с `<summary>Фрагмент</summary>` и текстом. У трёх обрезанных
  фрагментов (начало критериев пунктов 4 и 5, отклонение пункта 4 с
  середины абзаца) после ссылки — «показано не целиком: в пропущенной части
  слова, которые на сайте не используются; полный текст — по ссылке».
  Всего 40 фрагментов.
- В конце раздела: «Этот раздел собран тем же конвейером: план этого
  раздела.» — ссылка на план пункта 6 (без его фрагментов).
- **Шапка**: ссылка «Как собран этот сайт» (`#build`) между «Ограничения» и
  «Автор»; строки «в работе» нет. Раздел стоит после «Ограничений», перед
  подвалом.
- **Тест** `site/src/sections/build-story.test.ts` (14 тестов): порядок
  стадий; непустые тексты; каждый фрагмент совпадает со строками файла и
  даёт ссылку с `?plain=1#L`; у каждого события вне «Постановки» есть
  фрагмент из `docs/plans/`; «Постановка» — из `docs/specs/` и текст с
  «вручную» и «в диалоге с моделью»; показаны план, `-verify` и `-review`
  пунктов 3–5 и двух фикс-планов; нет фрагментов из документов пункта 6; у
  каждого фрагмента из `-verify.md` заявленный статус (`claim.verdict`)
  совпадает с первым словом после `## Итог` в файле, из `-review.md` —
  `claim.rejected` с числом `отклонено: N`; заголовки событий стадий
  проверки и ревью называют заявленный статус («отклонен» — только при
  `rejected > 0`), последний названный в заголовке итог — заявленный; PARTIAL и отклонённое замечание пункта 1 показаны; ровно
  три обрезанных фрагмента, и рядом с каждым в файле есть запретные слова;
  нет `SDD`/`Spec-Driven`; в авторских текстах (включая пометку обрезанного
  фрагмента) нет цифр, кроме номера пункта («пункт 4»). Тест не требует,
  чтобы итог был PASSED или `отклонено: 0` — только совпадения с файлом.

## 3. Pre-requisites

- Node.js 22, npm 10; `npm --prefix site ci`, если `site/node_modules` нет.
- Chrome с DevTools.
- Стенд — любой свободный порт; в примерах 4179. Проверка:
  `lsof -iTCP:4179 -sTCP:LISTEN` → пусто (4173 может держать чужой
  `vite preview`); занят — взять другой и подставлять его в §4.8 и §9.
- Из корня репозитория:
  ```bash
  npm --prefix site run build
  npm --prefix site run preview -- --port 4179 --strictPort
  ```
  Адрес: `http://localhost:4179/claude-code-harness/`.
- Правки §5 и §6 — только во временном клоне, не в рабочем дереве. `git
  clone` переносит только закоммиченное: прогон — после коммита фикса,
  рабочее дерево чистое (`git status --short` → пусто), иначе клон проверит
  старый код без `claim` и новых тестов:
  ```bash
  git clone . "$TMPDIR/harness-manual-6"
  npm --prefix "$TMPDIR/harness-manual-6/site" ci
  ```
  Команды §5 и §6 выполнять из клона; откат после каждой правки —
  `git -C "$TMPDIR/harness-manual-6" checkout -- .`; в конце клон удалить.
- Для §4.9 — push в `main` сделан тимлидом (агент push не делает).

## 4. Happy path

### 4.1. Шапка и место раздела

**Действие**: открыть стенд, просмотреть шапку; нажать «Как собран этот
сайт».
**Ожидание**: строки «Раздел «Как собран этот сайт» в работе.» нет; в списке
ссылок «… Ограничения · Как собран этот сайт · Автор»; после клика адрес
заканчивается на `#build`, заголовок «Как собран этот сайт» вверху экрана.
Порядок разделов: «Зачем», «Конвейер», «Устройство», «Ограничения», «Как
собран этот сайт», подвал «Автор».

### 4.2. Состав раздела

**Действие**: прокрутить раздел до конца.
**Ожидание**: вводная о прогоне пунктов 3, 4, 5; восемь подзаголовков
стадий в порядке из §1; у каждой стадии вводная и карточки событий с
бирюзовым заголовком; последний абзац — «Этот раздел собран тем же
конвейером: план этого раздела.», ссылка ведёт на
`…/blob/main/docs/plans/2026-10-11_1503_public-showcase-6-build-story.md`.
Слов «SDD» и «Spec-Driven Development» нет (Ctrl+F).

### 4.3. Фрагменты

**Действие**: у карточки «Спецификация — вручную» нажать «Фрагмент» под
подписью «Спецификация: часть про сайт».
**Ожидание**: раскрывается моноширинный блок, первая строка
`### Часть 2. Сайт, собранный через конвейер`; подпись — ссылка
«docs/specs/2026-10-11_public-showcase.md, строки 80–91». Повторный клик
сворачивает. Все 40 фрагментов свёрнуты при загрузке; подписи и ссылки
видны без раскрытия.

**Действие**: в стадии «Ревью другой моделью» найти карточку «Пункт 1: одно
замечание отклонено».
**Ожидание**: подпись «Отчёт ревью пункта 1: отклонённое замечание:
docs/plans/2026-10-11_1303_public-showcase-1-harness-snapshot-review.md,
строка 9» — «строка», а не «строки 9–9»; ссылка оканчивается на
`?plain=1#L9`.

**Действие**: в «Планах» у карточек пунктов 4 и 5 и в «Отклонениях» у
«Пункт 4: реализация остановилась…» прочитать подписи фрагментов.
**Ожидание**: после ссылки — «; показано не целиком: в пропущенной части
слова, которые на сайте не используются; полный текст — по ссылке»; у
остальных фрагментов этой пометки нет:
`[...document.querySelectorAll('#build figcaption')].filter(c => c.textContent.includes('не целиком')).length`
→ `3`.

**Действие**: в консоли DevTools:
```js
[...document.querySelectorAll('#build figcaption a')].filter(a => !a.href.includes('/blob/main/') || !a.href.includes('?plain=1#L')).length
```
**Ожидание**: `0`; `document.querySelectorAll('#build figure').length` → `40`.

### 4.5. Клавиатура

**Действие**: кликнуть в пустое место страницы рядом с разделом, затем Tab
до первой ссылки фрагмента, ещё Tab, Enter; Enter ещё раз.
**Ожидание**: фокус на «Фрагмент» виден (рамка 2px); Enter раскрывает, второй
Enter сворачивает; Tab дальше идёт по ссылкам и `summary` по порядку.

### 4.6. Ширина 360px и 1280px

**Действие**: DevTools → device toolbar 360px или сниппет iframe из §7
мануала `docs/manual/2026-10-11_1421_public-showcase-4-style-pipeline-scheme.md`
(`showAt(360)`, `showAt(1280)`); внутри раскрыть все фрагменты:
`document.querySelectorAll('details').forEach(d => d.open = true)`.
**Ожидание**: горизонтальной прокрутки нет
(`document.documentElement.scrollWidth <= innerWidth`); длинные пути и строки
фрагментов переносятся; карточки в одну колонку на любой ширине.

### 4.7. Тёмная тема

**Действие**: DevTools → Rendering → `prefers-color-scheme: dark`; раскрыть
пару фрагментов.
**Ожидание**: фон тёмный, текст кремовый, «Фрагмент» и заголовки карточек
светло-бирюзовые, фон фрагмента тёмный, текст читается; тёмного текста на
тёмном фоне нет.

### 4.8. Сеть

**Действие**: Network → Disable cache → перезагрузить; раскрыть несколько
фрагментов.
**Ожидание**: запросы только к `localhost:4179` (документ, JS, CSS, шесть
шрифтов); раскрытие фрагментов запросов не делает; ошибок в консоли нет.
Запрос `favicon.svg` к тому же адресу и строки со схемой `data:` ожидаемы —
это не сторонние домены, дефектом не считать. В сборке сайта `data:`-адресов
нет (`grep -c 'url(data:' site/dist/assets/*.css` → `0`); такие строки
порождают браузер или его расширения.

### 4.9. Опубликованный сайт (после push тимлидом)

**Действие**: дождаться workflow «Pages», открыть
`https://stels54.github.io/claude-code-harness/#build`; открыть 3–4 ссылки
фрагментов; повторить §4.8 на этом адресе; открыть с телефона через
мобильный интернет и с компьютера из РФ без VPN.
**Ожидание**: раздел на месте; GitHub показывает файл в режиме кода с
подсвеченными строками A–B, и они совпадают с текстом фрагмента (GitHub
дорисовывает строки длинного файла по мере прокрутки: если подсветки не
видно сразу, докрутить до номера строки — это не дефект); в Network
только `stels54.github.io`; на телефоне раздел читается без горизонтальной
прокрутки. Итог по доступу из РФ и телефону передать для записи в «Факты»
роадмапа.

## 5. Дополнительные сценарии: тест и сборка ловят расхождения

Все правки — во временном клоне из §3. Каждую правку откатывать
(`git -C "$TMPDIR/harness-manual-6" checkout -- .`) перед следующей.

### 5.1. Пропал маркер фрагмента
**Действие**: в `site/src/pipeline/fragment-sources.ts` у
`'build-plan5-port'` заменить `start` на `'- Порт приёмкиX'`;
`npm --prefix site run build`.
**Ожидание**: сборка падает с «Фрагмент «build-plan5-port» из docs/plans/…:
Маркер начала не найден: - Порт приёмкиX».

### 5.2. Событие без источника в `docs/plans/`
**Действие**: в `build-story.ts` у события `deviation-5-port` заменить
фрагмент на `frag('build-fact-raw', 'x')`; `npm --prefix site test`.
**Ожидание**: падает «у каждого события есть источник в docs/plans/».

### 5.3. Запрещённое слово
**Действие**: дописать в `text` события `review-4` слово «SDD»; тесты. У
`review-4` и `review-5` одинаковый текст «Ревьюер дефектов в диффе не
нашёл.» — искать событие по `id: 'review-4'`, а не поиском по тексту.
**Ожидание**: падает «нет запрещённых названий».

### 5.4. Цифра в авторском тексте
**Действие**: в `text` события `review-4` (найти по `id`, текст совпадает с
`review-5`, см. §5.3) написать «Ревьюер нашёл 0 дефектов»; тесты.
**Ожидание**: падает «нет цифр в авторских текстах, кроме номера пункта
роадмапа». Строка «Пункт 4: замечаний нет» тест проходит.

### 5.5. Рекурсия на собственный прогон
**Действие**: в `fragment-sources.ts` у `'build-review5-total'` поставить
путь `docs/plans/2026-10-11_1503_public-showcase-6-build-story-review.md`;
тесты.
**Ожидание**: падает «собственный прогон — только ссылкой» (и «показан
прогон пунктов сайта и фикс-планов»: пропал `-review.md` пункта 5).

### 5.6. Спецификация без пометки «вручную»
**Действие**: убрать «вручную» из текста события `spec`; тесты.
**Ожидание**: падает «спецификация — вручную, в диалоге с моделью».

## 6. Edge cases

- **Подмена статуса отчёта**. Действие (в клоне из §3): в
  `docs/plans/2026-10-11_1356_public-showcase-4-style-pipeline-scheme-verify.md`
  в строке после `## Итог` заменить `PASSED` на `PARTIAL`;
  `npm --prefix site test`. Ожидание: падает «заявленный статус отчёта
  совпадает с итогом в файле» (`expected { verdict: 'PASSED' } to deeply
  equal { verdict: 'PARTIAL' }`). Откатить; затем в
  `site/src/sections/build-story.ts` у `build-review4-total` заменить
  `rejected(0)` на `rejected(1)` при неизменном файле — падают тот же тест и
  «заголовки событий не расходятся с заявленным статусом». Откатить.
- **Документ прогона поправили выше фрагмента**: строки сдвигаются, плагин
  пересчитывает диапазон при сборке, тест «фрагменты совпадают…» зелёный;
  ссылки на `main` верны после push.

## 7. Фронтенд-нюансы и известные ограничения (багом не считать)

- Ссылки ведут на `main`, а не на тег (тег — пункт 7). До push номера строк
  на GitHub могут не совпадать с локальными файлами.
- Фрагменты критериев приёмки пунктов 4 и 5 и отклонения пункта 4 показаны
  частично — до или после строк со словами, которых на сайте быть не должно;
  подпись помечена «показано не целиком…», ссылка ведёт на точный диапазон.
- Таблицы вердиктов кросс-ревью планов в файлах не сохраняются, поэтому
  стадия «Ревью другой моделью» показывает только отчёты ревью диффа.
- Подписи фрагментов в нескольких карточках повторяются («Отчёт проверки
  фикса: итог») — у каждой своя ссылка на файл.
- Подсветки синтаксиса во фрагментах нет — исходный markdown.
- Тёмная тема и опубликованный адрес агентом не проверялись (DEFERRED в
  верификации) — §4.7, §4.9.
- Подпись ссылки на план этого раздела со строчной буквы («план этого
  раздела») — стоит в середине фразы, отмечено верификатором как косметика.
- Окно браузера расширения не сужается ниже ~606px: 360px и 1280px агент
  мерил в iframe.
