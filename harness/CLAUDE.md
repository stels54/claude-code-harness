# Личные инструкции

## Код
- Не добавляй комментарии, объясняющие очевидное.
- Правь ровно то, о чём попросили. Побочные улучшения — предлагай, не делай.
- Следуй конвенциям файла, в котором пишешь, а не своим предпочтениям.
- Пакетный менеджер определяй по lock-файлу проекта (`pnpm-lock.yaml` → pnpm,
  `yarn.lock` → yarn), а не по привычке.

## Проверка
- Используй тесты и линтер, которые уже есть в проекте. Новые инструменты не заводи.
- Прогоняй проверки после правок, не заявляй об успехе без запуска.

## Вопросы ко мне
- Вопросы задавай одним нумерованным блоком: один пункт = один вопрос,
  не растягивай на несколько сообщений.
- Формат пункта: контекст (файл/шаг) → вопрос → варианты `a) … b) …`
  с trade-off в пару слов → твоя рекомендация одной фразой.
- Буквенные варианты — чтобы я мог ответить коротко: «1b, 2a».
- Открытый вопрос без осмысленных вариантов задавай как есть —
  ложные альтернативы не выдумывай.

## Коммиты
- Коммит по плану из `docs/plans/` завершай trailer'ом с именем
  файла плана — последней строкой, через пустую строку от тела:

  Plan: 2026-07-18_1129_dashboard-1-1-json.md

- Правка кода, уже закоммиченного по плану, без нового плана —
  trailer `Fix-for:` с именем файла плана-виновника. Виновника
  определи по `git log`/`git blame` затронутых строк; дёшево не
  находится — пиши `Fix-for: не установлен`, не гадай.
- Закончил внеплановую правку или серию правок — сам предложи
  коммит с этим trailer'ом, не жди напоминания.
- Реализация плана принята (PASSED или моё подтверждение по
  DEFERRED) — тоже сразу предложи коммит.
- В одном коммите допустимо несколько trailer'ов, если батч
  планов неразделим по файлам.
- Только имя файла, без пути: планы переезжают в архив, имя
  уникально и не меняется.
- Правка вне контекста планов (конфиг, скрипт) — без trailer'а.

## Именование документов
- Документы в `docs/plans/`, `docs/roadmaps/` и `docs/manual/` именуются с
  сортируемым дата-префиксом: `ГГГГ-ММ-ДД_ЧЧММ_<kebab-case-slug>.md`.
- Префикс — момент создания документа: `date +%Y-%m-%d_%H%M`. Не выдумывай время.
- Производные документы наследуют префикс родителя, а не свой момент создания:
  `<план>-verify.md` — от плана, `-only-stand.md` — от основного мануала.
- План по пункту роадмапа — не производный документ: префикс свой, не роадмапа.
- Созданные файлы не переименовываются.
- В коммитимых документах (`PROJECT_LOG.md`, планы, мануалы) пути указывай
  только относительно корня репозитория.
- Запрещены машинные абсолютные пути (`/Users/...`, `/home/...`) и
  `file://`-ссылки.
