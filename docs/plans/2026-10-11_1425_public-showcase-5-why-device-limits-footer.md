# Plan: Разделы «Зачем», «Устройство», «Ограничения» и подвал

## Контекст
Роадмап: docs/roadmaps/2026-10-11_1236_public-showcase.md, пункт 5

Пункт 4 дал сайту стиль (токены `site/src/index.css`, раскладка
`site/src/App.css`), шапку с `HeroArt` и раздел «Конвейер» (`PipelineScheme`).
Теперь страница получает остальные разделы спецификации (часть 2, разделы 1,
3, 4, 5): «Зачем» на один экран, «Устройство», «Ограничения» и подвал «Автор».
Тексты разделов живут в модуле данных без DOM, чтобы тест мог проверить их
механически: каждое утверждение «Устройства» привязано к записи «Фактов»
роадмапа, нет слов «Spec-Driven Development»/«SDD» и цифр, стадия
спецификации упоминается только как отсутствующая. Порядок разделов — как в
спецификации: Зачем → Конвейер → Устройство → Ограничения → подвал.

## Окружение
- Node.js и npm, зависимости `site/` установлены (`site/package-lock.json`).
- Chrome-расширение (mcp__claude-in-chrome__*) для шага `browser-acceptance`
  на `npm --prefix site run preview` (`http://localhost:4173/claude-code-harness/`).
  Ширина 360px — только в iframe шириной 360px («Факты» пункта 3); клавиши
  доходят до страницы только после клика в неё («Факты» пункта 4). Нет

### Step 2 — sections-content
- **Цель**: тексты разделов и подвала в одном модуле данных.
- **Файл**: `site/src/sections/content.ts`
- **Изменение**: модуль без DOM-API (его типизирует и
  `tsconfig.node.json` через тест, «Факты» пункта 4) экспортирует типы
  `SectionItem { id, title, text }`, `Section { title, lead, items }`,
  `AuthorLink { label, href }` и константы:
  - `WHY` — «Зачем»: вводная одной фразой и три пункта — что теряется при
    обычной работе с ИИ-помощником: `requirements` (требования остаются в
    переписке и забываются), `completeness` (правка делается частично,
    соседние места и документация не трогаются), `verification` (результат
    принимается на слово, проверяет тот же, кто писал). Коротко, на один
    экран, без цифр.
  - `DEVICE` — «Устройство», пункты по «Фактам» пункта 2 и только им
    (якоря — шаг `test-sections-content`): `commands` — команды в markdown,
    команды основной цепочки пишут документы в `docs/` (роадмап, план,
    отчёт проверки, отчёт ревью, мануал), план кода не пишет, решения в точках
    остановки за человеком, коммит предлагается, а не делается;
    `verifier` — субагент получает только путь к плану, контекста
    реализации у него нет намеренно, проверяет по файлу плана и состоянию
    репозитория, итог PASSED/FAILED/PARTIAL; `cross-review` — Codex через
    `codex exec --sandbox read-only` в двух местах (план и дифф), без
    контекста обсуждения, файлов не меняет, каждое замечание проверяется по
    коду, один цикл; `hooks` — `notify.sh` (уведомления на `Notification` и
    `Stop`), `pipeline-clock.sh` (локальный журнал событий), оба не
    блокируют работу при сбое; `thin-layer` — почему тонкий слой поверх
    Claude Code без фреймворков: ядро — файлы команд, агент, общий
    `CLAUDE.md` и фрагмент настроек только с ключом `hooks`, ставится
    копированием в `~/.claude`.
  - `LIMITS` — «Ограничения»: `auto-vs-human` — автоматически: typecheck,
    линтер, тесты и сборка из корневого `CLAUDE.md`, которые запускает
    агент проверки, проверка утечек перед push; человеком: ответы на
    критичные вопросы и STOP, подтверждение DEFERRED, вкладка Network,
    тёмная тема, доступность сайта; `model-checks-model` — агент проверки и
    Codex тоже модели, это известный предел; `price` — подписка Claude Max и
    отдельно доступ к Codex; расход большой: один пункт роадмапа — это
    несколько полных проходов моделей по коду и документам (план,
    кросс-ревью, реализация, изолированная проверка, ревью диффа), точных
    цифр нет; `no-spec-stage` — отдельной стадии спецификации в конвейере
    нет, постановку человек готовит сам; `snapshot` — `harness/` —
    публичный снимок, обновляется вручную и отстаёт, а сайт собран рабочей
    версией конвейера.
  - `AUTHOR` — `name: 'Кирилл Жиркин'`, `links`: почта
    (`mailto:stels54@gmail.com`, подпись — адрес), Telegram
    (`https://t.me/stels54`, подпись `@stels54`), GitHub, LinkedIn,
    репозиторий (`REPO_URL`) — порядок по шагу `test-sections-content`, п. 6.
- **Референс**: `site/src/pipeline/steps.ts:1-40` (модуль данных с
  интерфейсом и константой); `README.md`, разделы «Шаги конвейера»,
  «Ограничения» (формулировки, уже сверенные с командами);
  `docs/roadmaps/2026-10-11_1236_public-showcase.md:124-270` («Факты»).
- **Риск**: формулировка, не покрытая якорем, проходит тест, но не сверена —
  при реализации каждое предложение `DEVICE` сверяется с «Фактами» глазами,
  лишнее убирается; тест ловит только отсутствие привязки пункта.
- **Проверка**: `npm --prefix site test` — тест шага
  `test-sections-content` зелёный; `npm --prefix site run typecheck` → exit 0.
