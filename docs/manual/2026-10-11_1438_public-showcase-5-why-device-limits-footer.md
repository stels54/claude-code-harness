## 3. Pre-requisites

- Node.js 22, npm 10; зависимости: `npm --prefix site ci`, если
  `site/node_modules` нет.
- Chrome с DevTools.
- Порт 4173 свободен: `lsof -iTCP:4173 -sTCP:LISTEN` → пусто. Занят чужим
  процессом — взять другой порт и подставлять его ниже.
- Из корня репозитория:
  ```bash
  npm --prefix site run build
  npm --prefix site run preview -- --port 4173 --strictPort
  ```
  Адрес: `http://localhost:4173/claude-code-harness/`.
- Для §4.9 — push в `main` сделан тимлидом (агент push не делает).

## 4. Happy path

### 4.1. Порядок разделов

**Действие**: открыть страницу, прокрутить сверху вниз. В консоли:
`[...document.querySelectorAll('h2')].map(h => h.textContent)`.
**Ожидание**: `["Зачем", "Конвейер", "Устройство", "Ограничения", "Автор"]`;
схема «Конвейер» выглядит и работает как в пункте 4; подвал — последний
блок страницы, отделён линией сверху.

### 4.2. Тексты и подвал

**Действие**: прочитать каждый раздел.
**Ожидание**:
- у каждого раздела заголовок, вводная строка и карточки пунктов с
  заголовком бирюзового цвета и охристой линией слева; на широком окне
  карточки в две-три колонки;
- вводные: «Зачем» — «В обычном разговоре с ИИ-помощником работа идёт
  быстро, но три вещи теряются по дороге.»; «Устройство» — «Команды, агент
  проверки с изолированным контекстом, ревью другой моделью и хуки — обычные
  файлы для Claude Code.»; «Ограничения» — «Что конвейер не делает и чего
  стоит.»;
- «Команды»: основная цепочка — шесть шагов схемы от /roadmap до /manual,
  /verify, /plan-fix и /fix-tests вне её; остановка названа STOP — команда
  ждёт решения человека;
- «Ревью другой моделью»: шаг необязательный — флаг --no-codex в /plan,
  без codex пропуск с ⏭️;
- «Хуки»: журнал `~/.claude/pipeline-clock.jsonl`, нужен jq, в строке —
  время, событие, id сессии, рабочий каталог и до двухсот символов первой
  строки запроса или задания субагенту;
- «Тонкий слой без фреймворков»: внешние программы jq, terminal-notifier или
  notify-send, Codex CLI; позиция автора помечена «Выбор автора:»;
- «Автоматически и руками»: общая формулировка за человеком и отдельная
  фраза «Для этого сайта руками проверялись …»;
- в «Цена» — подписка Claude Max, Codex CLI для ревью другой моделью (без
  него шаг пропускается), расход описан словами, чисел нет;
- нигде на странице нет «SDD», «Spec-Driven Development» (Ctrl+F) и цифр в
  текстах разделов;
- подвал: «Автор», «Кирилл Жиркин» и пять ссылок из §1; наведение на каждую
  показывает адрес из §1; ссылки hh.ru нет.

### 4.3. «Зачем» на один экран

**Действие**: окно браузера такое, что в консоли `innerWidth >= 1200` →
`true` (критерий — `innerWidth`, а не размер окна с рамкой и панелями);
затем `document.getElementById('why').offsetHeight <= innerHeight`.
**Ожидание**: `true` (при приёмке — высота 353px при высоте окна около
800px); раздел целиком виден без прокрутки, когда его заголовок у верхнего
края.

### 4.4. Якоря шапки

**Действие**: по очереди нажать «Зачем», «Конвейер», «Устройство»,
«Ограничения», «Автор».
**Ожидание**: адрес получает `#why`, `#pipeline`, `#device`, `#limits`,
`#author`, страница прокручивается к разделу. «Назад» в браузере после
одного нажатого якоря возвращает к шапке; после пяти подряд — к предыдущему
якорю (`#limits`), каждое следующее «Назад» — ещё на якорь раньше.

### 4.5. Клавиатура

**Действие**: кликнуть по пустому месту над заголовком, нажимать Tab.
**Ожидание**: фокус: «Репозиторий на GitHub» → «README» → «Зачем» →
«Конвейер» → «Устройство» → «Ограничения» → «Автор» → кнопки схемы
`/roadmap` … `/fix-tests` → ссылки подвала по порядку. У каждого элемента
видна обводка 2px. Enter на якоре переходит к разделу; Enter на кнопке
схемы раскрывает шаг. Карточки разделов фокус не получают — это текст.

### 4.6. Ширина 360px

**Действие**: DevTools → Toggle device toolbar, Responsive, ширина 360,
перезагрузить; прокрутить до подвала; в консоли
`document.documentElement.scrollWidth <= innerWidth`.
**Ожидание**: `true`; карточки в одну колонку; ссылки шапки и подвала
переносятся на несколько строк; адрес почты не вылезает за край.

### 4.7. Тёмная тема

**Действие**: DevTools → Rendering → «Emulate CSS media feature
prefers-color-scheme» → `dark` (или тёмная тема ОС).
**Ожидание**: карточки разделов и подвал на тёмном фоне, текст кремовый,
заголовки карточек светло-бирюзовые, линии карточек и подвала видны,
ссылки подвала светло-оранжевые; тёмного текста на тёмном фоне нет.

### 4.8. Сеть (ручной пункт)

Агент вкладку Network не проверяет — пункт только для человека.

**Действие**: DevTools → Network, включить «Disable cache» (обязательно:
без него js/css отвечают 304, а `favicon.svg` может не запрашиваться — это
не дефект), перезагрузить.
**Ожидание**: запросы только к `localhost:4173`: документ, `index-<хэш>.js`,
`index-<хэш>.css`, `favicon.svg`, шесть шрифтов `/claude-code-harness/fonts/`;
к `t.me`, `github.com`, `linkedin.com` запросов нет — это только ссылки.

### 4.9. Опубликованный сайт (после push тимлидом)

**Действие**: дождаться зелёного workflow «Pages», открыть
https://stels54.github.io/claude-code-harness/ с компьютера из РФ без VPN
(DevTools → Network) и с телефона через мобильный интернет.
**Ожидание**: новые разделы и подвал на месте; в Network только
`stels54.github.io`; на телефоне нет горизонтальной прокрутки, якоря
работают касанием. Итог сообщить для записи в «Факты» роадмапа.

## 5. Дополнительные сценарии: тест текстов ловит нарушения

Каждый сценарий — временная правка во временном клоне, рабочее дерево не
трогать. Из корня репозитория:

```bash
CLONE="$(mktemp -d)/repo"
git clone -q . "$CLONE"
npm --prefix "$CLONE/site" ci
```

Пути ниже — относительно `$CLONE`, тест — `npm --prefix "$CLONE/site" test`.
После каждого сценария откатить: `git -C "$CLONE" checkout -- .`; в конце —
`rm -rf "$CLONE"`.

### 5.1. Пропала запись «Фактов»

**Действие**: в `docs/roadmaps/2026-10-11_1236_public-showcase.md` в записи
об агенте `verifier` заменить «контекста реализации у него нет намеренно»
на «контекста реализации у него нет»; `npm --prefix site test`.
**Ожидание**: падает «каждый пункт «Устройства» привязан к «Фактам»»
(`expected … to contain 'контекста реализации у него нет намеренно'`).

### 5.2. Пункт «Устройства» без привязки

**Действие**: в `site/src/sections/content.ts` поменять id `'hooks'` на
`'hooks-x'`; `npm --prefix site test`.
**Ожидание**: падают «состав и порядок пунктов» и «каждый пункт
«Устройства» привязан к «Фактам»» (ключи таблицы якорей не совпадают с id).

### 5.3. Цифра в тексте

**Действие**: в `content.ts` в тексте пункта «Цена» дописать «за 3 дня»;
`npm --prefix site test`.
**Ожидание**: падает «раздел LIMITS › нет цифр».

### 5.4. Запрещённое слово и спецификация

**Действие**: в `content.ts` во вводную «Устройства» дописать «Это SDD.»;
тест. Откатить, затем в пункт «Команды» дописать «по спецификации»; тест.
**Ожидание**: первая правка — падает «нет запрещённых названий»; вторая —
«спецификация упомянута только как отсутствующая стадия».

### 5.5. Ссылка hh.ru в подвале

**Действие**: в `AUTHOR.links` добавить шестую ссылку `https://hh.ru/…`;
тест.
**Ожидание**: падает «подвал «Автор»» на deep-equal списка адресов
(`toEqual`: лишний шестой адрес); до проверки `hh.` тест не доходит.

## 6. Edge cases

- **Бандл**: `grep -c -E 'SDD|Spec-Driven' site/dist/assets/*.js` → `0`;
  `grep -c 'Пункт 6 — Раздел' site/dist/assets/*.js` → `0` (роадмап в
  бандл не попал: тест читает его с диска).
- **Внешние адреса в JS**: `grep -rhoE 'https?://[^"'"'"' )]+' site/dist
  --include='*.js' | sort -u` — по сравнению с пунктом 4 добавились только
  адреса подвала (`t.me`, `github.com/stels54`, `www.linkedin.com`);
  `http://localhost:4173/…` в бандле — текст фрагмента мануала пункта 3, не
  запрос.
- **Якоря**: `scripts/check-links.sh` → `check-links: 0 нарушений`; удалить
  временно `id="limits"` в `InfoSections.tsx` → скрипт сообщает о битом
  `#limits` (откатить).

## 7. Фронтенд-нюансы и известные ограничения (багом не считать)

- «Один экран» агент измерял в iframe 1280×800: окно расширения не меняет
  размер (`resize_window` оставил viewport 400×570). На настоящем широком
  окне это проверяет человек (§4.3).
- Тёмную тему, Network на опубликованном адресе и доступ из РФ агент не
  проверял — это ручные пункты (§4.7, §4.9).
- На 360px «Зачем» длиннее экрана — «один экран» задан для широкого окна
  (допущение плана).
- Карточки разделов — статичный текст: не раскрываются и не получают фокус.
- Ссылка на репозиторий в подвале ведёт на `main`-страницу репозитория, без
  тега (теги — пункт 7); `scripts/check-links.sh` проверяет только ссылки
  `blob`/`tree`, её он не видит.
- Агентская приёмка шла на порту 4174: 4173 держал не отвечающий preview
  другой сессии.
