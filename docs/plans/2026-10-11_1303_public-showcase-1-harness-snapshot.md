# Plan: Публичный снимок ядра и проверка на утечки

## Контекст
Роадмап: docs/roadmaps/2026-10-11_1236_public-showcase.md, пункт 1

Кладём в `harness/` очищенную копию ядра конвейера из рабочего `~/.claude`
(команды `plan`, `implement`, `verify`, `code-review`, `plan-fix`, `fix-tests`,
`manual`, `roadmap`, агент `verifier`, хуки `notify.sh` и `pipeline-clock.sh`,
`CLAUDE.md`, фрагмент `settings.json` с хуками), вырезаем ссылки на журнал
lessons, добавляем `LICENSE` (MIT) и два скрипта в `scripts/`: проверку
репозитория на утечки (локальный список запрещённых строк, шаблоны ключей,
абсолютные пути домашней папки) и проверку, что `harness/` не ссылается на
файлы вне себя и не упоминает lessons. Это нужно до первого push публичного
репозитория: следующие пункты роадмапа описывают и публикуют именно этот снимок.

## Окружение
- Источник ядра — рабочий `~/.claude`, только чтение.
- Список запрещённых строк — `~/.config/harness-publish/denylist.txt` (вне git,
  существует). Его содержимое не выводится в консоль и не попадает ни в один
  файл репозитория.
- `bash`, `grep`, `sed`, `find`, `git` — стандартные утилиты macOS; `jq` — только
  для сверки фрагмента настроек при реализации, скрипты от него не зависят.
- Для ручного шага `manual-clean-env-plan` — Claude Code с возможностью войти в
  аккаунт в отдельном `CLAUDE_CONFIG_DIR`.

### Step 7 — leak-check-script
- **Цель**: скрипт проверки репозитория на утечки.
- **Файл**: `scripts/check-leaks.sh`
- **Изменение**: исполняемый bash-скрипт, совместимый с bash 3.2 и BSD grep.
  - Вход: необязательный аргумент — корень проверяемого git-репозитория
    (по умолчанию `git rev-parse --show-toplevel` от текущего каталога).
    Путь к списку — `$HARNESS_DENYLIST`, по умолчанию
    `$HOME/.config/harness-publish/denylist.txt`.
  - Список: из файла отбрасываются пустые строки, строки из пробелов и строки
    с `#` в начале, `\r` в концах строк срезается. Файла нет или после
    фильтрации он пуст — сообщение в stderr и выход `2` (проверка не
    пропускается).
  - Охват: все файлы `git ls-files --cached --others --exclude-standard`
    (отслеживаемые и новые неигнорируемые), существующие на диске; бинарные
    файлы пропускаются (`grep -I`).
  - Категории: `denylist` — вхождение любой строки списка без учёта регистра
    (`grep -F -i -f`); `key` — шаблоны `AKIA[0-9A-Z]{16}`,
    `gh[pousr]_[A-Za-z0-9]{36,}`, `github_pat_[A-Za-z0-9_]{22,}`,
    `sk-[A-Za-z0-9_-]{20,}`, `xox[abprs]-[A-Za-z0-9-]{10,}`,
    `AIza[0-9A-Za-z_-]{35}`, `lin_api_[A-Za-z0-9]{20,}`,
    `-----BEGIN ([A-Z]+ )*PRIVATE KEY-----`; `home-path` —
    `/Users/[A-Za-z0-9_][A-Za-z0-9_.-]*` и `/home/[A-Za-z0-9_][A-Za-z0-9_.-]*`
    (плейсхолдеры вида `/Users/...` не совпадают: первый символ — точка).
  - Вывод: на каждое совпадение строка `<файл>:<строка>: <категория>` —
    без текста строки и без совпавшей подстроки, чтобы содержимое списка не
    попадало в консоль и в отчёты; в конце `check-leaks: N совпадений`.
    Выход `0` при N = 0, `1` при N > 0.
- **Референс**: — (самописных скриптов в репозитории нет; `git ls-files` на
  момент планирования: `.gitignore`, `docs/linkedInwallpaper.png`, роадмап,
  спецификация)
- **Риск**: пустая строка в `-f` совпадает со всем — отсюда фильтрация;
  шаблоны в тексте самого скрипта не должны совпадать сами с собой (после
  `[`/`(` в литерале шаблона стоит символ вне класса); `grep` в интерактивном
  zsh — функция-обёртка, скрипт под `bash` вызывает системный `grep`.
- **Проверка**: в `mktemp -d` создать git-репозиторий с файлом, куда строки
  генерируются при запуске (литералы в план не пишутся): `AKIA` + 16 символов
  `A`; `/Users/` + `probeuser` + `/x`; синтетическая строка `zzleakprobe`.
  Временный список с `zzleakprobe`, пустой строкой и комментарием `#x`.
  `HARNESS_DENYLIST=<врем. список> scripts/check-leaks.sh <врем. репо>` →
  выход `1`, ровно 3 строки совпадений (`denylist`, `key`, `home-path`),
  в выводе нет `zzleakprobe` и `probeuser`. С `HARNESS_DENYLIST=<несуществующий>`
  → выход `2`. Со списком только из пустой строки и комментария → выход `2`.
  Временные каталоги удалить.
- **dependsOn**: —

### Step 8 — harness-refs-check-script
- **Цель**: скрипт проверки, что `harness/` самодостаточен и не упоминает lessons.
- **Файл**: `scripts/check-harness-refs.sh`
- **Изменение**: исполняемый bash-скрипт (bash 3.2, BSD grep). Вход —
  необязательный корень репозитория (по умолчанию `git rev-parse
  --show-toplevel`), проверяется `<корень>/harness`. Нарушения:
  - `lessons` — любое вхождение `lesson` без учёта регистра в любом файле;
  - `command` — slash-команда в `*.md`: токен `/<имя>` из `[a-z][a-z-]*`,
    перед которым начало строки, пробел, `(`, `«`, `` ` `` или `"`, а после —
    не буква, не `-` и не `/`; нет файла `harness/commands/<имя>.md`;
  - `path` — путь `~/.claude/<путь>` или `$HOME/.claude/<путь>` в любом файле;
    нет файла `harness/<путь>`; исключение — `pipeline-clock.jsonl` (лог,
    который создаёт хук, а не публикуемый файл);
  - `agent` — `субагент`/`субагента`/`субагентом` и далее `` `<имя>` ``; нет
    `harness/agents/<имя>.md`;
  - `skill` — `скилл <имя>` или `` скилл `<имя>` ``; нет `harness/skills/<имя>/`.
  Вывод: `<файл>:<строка>: <категория>: <токен>` (токены — публичные имена
  команд и путей), в конце `check-harness-refs: N нарушений`; выход `0`/`1`.
  Нет каталога `harness/` — выход `2`.
- **Референс**: токены в источнике на момент планирования (`grep -o -h -E`
  по 10 md-файлам ядра): `/implement` ×13, `/plan` ×13, `/plan-fix` ×1,
  `/roadmap` ×3 — все публикуются; `субагент* \`verifier\`` —
  `~/.claude/commands/implement.md:146`, `~/.claude/commands/code-review.md:104`;
  `$HOME/.claude/…` — `~/.claude/hooks/pipeline-clock.sh:4` и команды хуков в
  `settings.json`; `скилл lessons` — `plan.md:286`, `implement.md:73`,
  `CLAUDE.md:44` (убираются шагами 2–4).
- **Риск**: ложные срабатывания на пути проекта пользователя (`docs/plans/`,
  `/home/...` в `CLAUDE.md`) — их отсекает правило «после токена не `/`» и
  требование пробела/скобки перед `/`; ссылки на файлы целевого проекта
  (`docs/plans/`, `package.json`) скрипт сознательно не проверяет — см. «Решения».
- **Проверка**: в `mktemp -d` собрать минимальную фикстуру `<tmp>/harness`,
  не зависящую от состояния настоящего `harness/`: файлы
  `commands/plan.md`, `agents/verifier.md`, `hooks/notify.sh` и
  `commands/demo.md` со строками — допустимые: `/plan`,
  `` субагентом `verifier` ``, `$HOME/.claude/hooks/notify.sh`,
  `~/.claude/pipeline-clock.jsonl`, `` `/home/...` ``, `docs/plans/`;
  нарушения: `/review`, `~/.claude/commands/git-report.md`, `скилл foo`,
  `lessons`. `scripts/check-harness-refs.sh <tmp>` → выход `1`, ровно 4
  нарушения с категориями `command`, `path`, `skill`, `lessons` (допустимые
  строки не срабатывают). Без каталога `harness/` в `<tmp2>` → выход `2`.
  Временный каталог удалить. Выход `0` на настоящем `harness/` проверяется в
  run-checks-repo (до шагов чистки там ещё есть lessons).
- **dependsOn**: snapshot-copy-core

### Step 10 — manual-clean-env-plan
- **Цель**: ручная приёмка: `harness/` в чистом окружении доводит `/plan` до
  файла плана.
- **Файл**: — (действие пользователя)
- **Изменение**: пользователь выполняет:
  1. `export CLAUDE_CONFIG_DIR=$(mktemp -d)` (рабочий `~/.claude` не трогается);
  2. копирует `harness/commands`, `harness/agents`, `harness/CLAUDE.md` в
     `$CLAUDE_CONFIG_DIR`; `settings.json` с хуками в тестовый каталог НЕ

     `$HOME/.claude/…` и писали бы в рабочий `~/.claude`, а на `/plan` хуки не
     влияют;
  3. в пустом временном git-репозитории запускает `claude`, входит в аккаунт и
     вызывает `/plan` на простой задаче (например, «добавить файл hello.txt со
     строкой hello»);
  4. сообщает в сессии итог: путь созданного файла в `docs/plans/` или текст
     ошибки о недостающем файле/команде/агенте.
- **Референс**: —

  недостающих файлов; нужен вход в аккаунт в новом каталоге конфигурации.
- **Проверка**: пользователь подтвердил, что `/plan` создал файл плана без
  ошибок о недостающих файлах. Верификатор ставит ⏸️ DEFERRED (нужна ручная
  приёмка).
- **dependsOn**: run-checks-repo

- Группа B (без зависимостей): settings-hooks-fragment, license-mit,

## Финальный проход
- run-checks-repo — после всех правок и обновления роадмапа.
- manual-clean-env-plan — действие пользователя после реализации.

## Критерии приёмки
1. `scripts/check-leaks.sh` на репозитории даёт 0 совпадений по списку
   запрещённых строк, шаблонам ключей и абсолютным путям домашней папки, а на
   подложенных в временный репозиторий утечках каждой категории — находит их,
   не печатая совпавший текст; без списка завершается ошибкой.
2. `scripts/check-harness-refs.sh` даёт 0 нарушений: в `harness/` нет
   упоминаний lessons, slash-команд, агентов, скиллов и путей `~/.claude/…`,
   которых нет в `harness/`; на подложенных нарушениях — находит их.
3. `harness/` содержит ровно ядро: 8 команд, агент `verifier`, 2 хука,
   `CLAUDE.md`, `settings-hooks.json` только с ключом `hooks`; тексты
   отличаются от рабочего `~/.claude` только удалёнными ссылками на lessons.
4. В корне есть `LICENSE` с текстом MIT.
5. Ручная проверка (шаг manual-clean-env-plan): `harness/`, скопированный в
   чистый `CLAUDE_CONFIG_DIR`, доводит `/plan` на простой задаче до файла
   плана без ошибок о недостающих файлах.

## Не делаем
- README, «Факты» с описанием шагов конвейера — пункт 2 роадмапа.
- Хук pre-push и запуск проверки в CI — пункт 3 роадмапа.
- Правки рабочего `~/.claude` и самого списка запрещённых строк.
- Проверку ссылок `harness/` на файлы целевого проекта пользователя
  (`docs/plans/`, `package.json`, `docker-compose.yml`, `PROJECT_LOG.md`) —
  это файлы проекта, где работает конвейер, а не файлы харнеса.
- Сканирование бинарных файлов (`docs/linkedInwallpaper.png`) на строки и
  метаданные: `grep -I` их пропускает.
- Сканирование истории git: репозиторий молодой, проверяется рабочее дерево.
- Шаблоны ключей сверх перечисленных в шаге leak-check-script.
- Проверку хуков в чистом окружении: они пишут по путям `$HOME/.claude/…`,
  ручная приёмка идёт без них.
- Переписывание текстов команд сверх удаления ссылок на lessons.

## Решения
- Состав ядра → 8 команд (`plan`, `implement`, `verify`, `code-review`,
  `plan-fix`, `fix-tests`, `manual`, `roadmap`), `agents/verifier.md`,
  `hooks/{notify.sh,pipeline-clock.sh}`, `CLAUDE.md`, фрагмент `settings.json`
  с хуками; `from-linear`, `review`, `git-report` и скилл `lessons` не
  публикуются (решение пользователя).
- Рабочий `~/.claude` → только чтение (решение пользователя).
- Список запрещённых строк → `~/.config/harness-publish/denylist.txt`, его
  строки не записываются ни в один файл репозитория; документы ссылаются только
  на путь (решение пользователя).
- Проверка «`harness/` в чистом окружении доводит `/plan` до файла плана» →
  ручной шаг пользователя через отдельный `CLAUDE_CONFIG_DIR`, verify ставит
  ему DEFERRED (решение пользователя).
- Инструменты проверки → bash и стандартные утилиты macOS, новых не заводим
  (решение пользователя).
- Проверка шага clean-plan-lessons `grep -c '( *)'` → `0` (по ходу /implement)
  → заменена на «равен счётчику по источнику»: в исходном `plan.md` два
  совпадения `` `it()` `` в тексте правила, ожидание `0` было ошибкой плана.
  Поправка исполнителя, на изменение не влияет; подтверждена пользователем.
- Шаблон ключа `sk-…` в leak-check-script (по ходу /implement) → с левой
  границей `(^|[^A-Za-z0-9])sk-[A-Za-z0-9_-]{20,}`: без неё шаблон ловит
  обычные слова вида `task-…`/`risk-…` с длинным хвостом. Поправка
  исполнителя; подтверждена пользователем.
- Принять реализацию с DEFERRED по шагу manual-clean-env-plan? → принять:
  ручной прогон `/plan` в чистом `CLAUDE_CONFIG_DIR` выполняет отдельный
  тестировщик по мануалу после коммита.
- «Ссылка на файл вне `harness/`» → проверяются ссылки на сущности харнеса:
  slash-команды, агенты, скиллы, пути `~/.claude/…`/`$HOME/.claude/…`. Пути
  целевого проекта не считаются ссылками харнеса.

## Допущения
- Фрагмент настроек называется `harness/settings-hooks.json` и содержит
  объект `{"hooks": …}` — его можно слить в `settings.json` как есть.
- Раздел `CLAUDE.md` «Харнес» удаляется целиком: оба его пункта — про
  неопубликованный журнал (по аналогии с допущением роадмапа о шагах
  «подключи скилл lessons»).
- Упоминание `PROJECT_LOG.md` в `CLAUDE.md` остаётся: это пример коммитимого
  документа проекта, не ссылка на файл харнеса.
- `$HARNESS_DENYLIST` переопределяет путь к списку — нужно для проверки
  скрипта на временном списке; по умолчанию путь из спецификации.
- Скрипт печатает только файл, строку и категорию совпадения: иначе вывод
  проверки (в том числе вставленный в `-verify.md`) раскрыл бы строки списка.
- Копирайт в `LICENSE` — имя автора из `git config user.name` в порядке
  «Имя Фамилия»: `Kirill Zhirkin`.
- `pipeline-clock.jsonl`, упомянутый в `pipeline-clock.sh`, — выходной лог хука,
  а не публикуемый файл; исключение в проверке ссылок.
